# 订阅链接使用客户端 email 的设计

日期：2026-10-16

## 目标与范围

用户需要仅凭订阅链接辨认对应的 3x-ui client，减少把链接发错人的风险。`clash-sub` 对外生成的所有订阅链接都以该 client 在 3x-ui 的 `email` 字段结尾。这里的 `email` 可以是 `42vio` 这样的用户名。链接中的随机部分仍负责保密；可读字段不承担鉴权。

本次更改 `clash-sub` 的链接格式、状态迁移、路由和显示。3x-ui 的本机 Clash 订阅仍是 `clash-sub` 的自建节点来源；其设置与 `sub_id` 不变。对外路径前缀 `/s/` 不变。旧的对外链接在迁移成功后无需继续可用。

## 链接格式

主令牌为 16 字节安全随机数的无填充 URL-safe Base64（22 字符），后接 `-` 和 3x-ui client 的原样 `email`。例如：

```text
https://sub.example.com/s/<22位随机令牌>-42vio/Clash-Compat.yaml
```

普通用户只有 `Clash-Compat.yaml`；owner 继续拥有 `Clash-Compat.yaml`、`Clash-Balance.yaml`、`Clash-Airport.yaml` 和机场镜像 `AmyTelecom.yaml`。owner 的 `Clash-Airport.yaml` 使用从 owner 主令牌经单向散列派生的独立 22 字符随机部分，后接相同的 email；该派生令牌只授权机场配置及其 provider。`Clash-Compat.yaml` 和 `Clash-Balance.yaml` 内的 `AmyTelecom` provider，以及单列的机场镜像链接，使用 owner 主令牌。

`email` 保留大小写，长度为 1–254 个字符，仅允许 ASCII 英文字母、数字及 `.`、`_`、`@`、`+`、`-`。程序在生成令牌或路由之前校验；不符合时返回稳定错误码，不把原始值拼入 Nginx 配置或错误输出。该字符集无需百分号编码，并涵盖当前约定的客户端名称与普通邮箱。邮箱会在 URL、浏览器历史及接收者侧可见；不要把它当成秘密。随机部分继续由安全随机源生成，轮换链接时重新生成；修改 email 时保留随机部分，仅更换可读后缀。

令牌解析使用固定的 22 字符随机部分和紧随其后的 `-`，后续全部字符都属于 email，因此带 `-` 的邮箱不会产生分隔歧义。Nginx 只为完整令牌与允许的文件名生成精确匹配路由；未知令牌、错误文件名或把 owner 机场专用令牌用于其他配置仍被拒绝。

## 状态与迁移

现有状态文件为 v1，保存 43 字符随机部分、6 字符识别码与 `readable_code`。新状态格式升级为 v2，保存 22 字符随机部分、client email、令牌和现有用户及发布信息，不再保存随机可读识别码。迁移前保留 v1 读取、写入与路由渲染供恢复及管理操作使用；机场派生令牌按明确的状态版本生成，避免新旧格式重叠时误判；v2 写入和校验只接受新格式。正常读操作不隐式迁移或发布，避免 `links` 展示尚未生效的 URL。

升级后的第一次 `clash-sub sync` 执行一次全量迁移：读取 v1 与 3x-ui 快照，为每个仍在 3x-ui 中的 client 生成新令牌，重新准备所有启用用户的配置，特别是重新生成 owner 配置中的 provider URL；随后通过现有运行时激活事务一起发布配置、Nginx 路由和 v2 状态。迁移阶段若任一必需用户准备或激活失败，丢弃候选并保留原状态与路由；修复后可重试。成功后新路由中不保留 v1 令牌，旧链接失效。已删除的旧版用户不纳入迁移候选，避免其历史 email 阻塞迁移；停用用户不发布链接。

迁移前 `links` 不输出尚未发布的 v2 URL，而提示先运行 `sync`；迁移后按 client ID 排序显示 `email`、client ID 和实际生效的 URL。对外链接中的 email 与状态中发布时的 email 一致。`status` 可显示待同步状态，但不泄露随机令牌。

以后 3x-ui client 的 `email` 改动在下一次 `sync` 成功时生效。该 client 的令牌后缀和路由一起更换，旧后缀对应的路由撤销；若是 owner，重新生成引用 provider URL 的配置。同步前继续使用已发布的旧状态与链接，并提示待同步，避免发出未生效的新 URL。普通 `sync` 仍保留现有按用户报告错误的语义；某用户准备失败时，该用户保持原状态和路由。`rotate-link` 保留当前 email，并重新生成 16 字节随机部分；owner 的机场专用派生令牌和 provider URL 随之更新。

Owner 回滚不得恢复引用旧令牌或旧 email 的 provider URL。`rollback` 只能接受 provider URL 与当前已发布 owner 令牌一致的历史发布；不一致时返回现有回滚错误，并保持运行时不变。普通用户的历史配置不含机场 provider，继续沿用现有回滚规则。

## 组件边界与失败处理

- `state.py` 负责 v1 读取、v2 校验与写入、令牌生成、email 校验和按 email 变更生成候选状态。
- `service.py` 负责在 `sync` 中协调迁移、配置重新生成与激活；`links` 只返回已发布链接，`rotate-link` 沿用原子激活流程。
- `nginx.py` 只根据已校验的完整令牌生成精确路由；`/s/` 和内部元数据路径保持不变。
- `cli.py` 显示 client ID、email、订阅链接及“机场镜像链接”标签；不另打印裸随机令牌。

输入非法、候选生成失败或激活失败时，错误只包含稳定错误码与必要的 client ID，不包含订阅 URL、随机令牌或未经校验的 email。现有运行时事务负责恢复中断状态；迁移不得让 v2 状态与 v1 路由同时成为已发布版本。

## 验收

1. 新用户、owner 与普通用户的 URL 均符合 22 字符随机部分加原样 email；owner 的机场专用令牌仍与主令牌隔离。
2. v1 状态可在第一次成功的 `sync` 中迁移，发布后旧 URL 不再匹配；任一步失败时旧状态、配置和路由保持可用，重试可成功。
3. 修改 client email 后，在成功的 `sync` 前只显示已发布旧链接并提示待同步；成功后新链接可用、旧链接失效。含连字符和大小写的 email 原样保留；非法字符安全拒绝。
4. 轮换链接更换随机部分并保持 email；owner 的 `Clash-Airport.yaml`、`AmyTelecom.yaml` 和配置内 provider URL 一致，普通用户仍不能访问机场文件。
5. Owner 回滚到引用旧 provider URL 的发布被拒绝，当前订阅仍可用。
6. 私密状态文件继续保存完整令牌；错误、状态摘要与日志不额外暴露随机部分或未经校验的 email。`links` 和 `rotate-link` 仅在完整订阅 URL 中显示令牌。既有订阅响应头、刷新周期和 3x-ui 本机来源行为不变。
